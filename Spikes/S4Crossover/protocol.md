# S4 交错试验预注册（一次）

此前两组的 180 个有效 WindowServer 秒读数来自六个不同进程、六个不同窗口。第一组按时间排列的均值为 24.890%、38.307%、36.080%，第二组为 40.013%、43.023%、27.843%。每组只有中间阶段打开动画，时间与场景完全重合。空窗漂移 +11.190、−12.170 个百分点，超过原容限。仅凭这些读数无法估计中段同时刻的背景，插值需要另外假设漂移形状。先前 15 Hz 初探两端漂移 −14.140，默认呼吸两次超线的观测值仍予保留。

## 设计、失败方式与判定

1. 一个新签名夹具进程、一个浮窗，一次启动。C 使用生产探针的 LayerBreath 和 15/15/15 偏好；E、N+、N− 均是真正的 SwiftUI Color.clear。每段卸载前一视图和动画并重新安装对应根，包括空对空转换。浮窗始终采用生产探针同一参数。估计量为可见呼吸候选相对空壳的全部增量（含绘制图形）。无静态图形组。该窗随时间共用进程缓存，内存同时报告绝对值与配对差。
2. 八个时间块，每块有相邻的一对 C/E 和相邻的一对 N+/N−。注册时分别独立打乱三列各四正四反的顺序（对的先后、C/E 的方向、N+/N− 的方向），完整冻结为 schedule.json。每段切换后至少 2 秒丢弃；begin 回执后运行一次 footprint；它结束后再等至少 1 秒，单独启动 top -l 6 -s 1 同采两个 PID。丢弃每段 top 首帧，余下五个 1 秒读数全取，四个标签各 40 个，无筛选。每段 top 退出后才发结束信号。夹具在收到下一段信号前不切换。
3. 身份、时间、显示或实现异常均待验。要求所有段首尾的 AppKit 与 CG PID/窗号相符，同一 WindowServer、屏幕、缩放、材质、层级、窗框、模式不变，192×192 pt、可见、未全遮挡、显示器醒着、会话未锁；正式采集期间若有窗口移动、尺寸、遮挡、屏幕或 backing 变更通知则整轮待验。C 两端均需动画与图形挂载、15/15/15，空壳两端均无图形/动画。采样进程的实际调用区间完全落在同段回执内，首帧到末帧 top 的本地整秒差 5–7 秒，相邻帧整秒差 1–2 秒。每段有 1 个原始物理字节数和 5 对有效 CPU 样本。任一缺失均不补测。
4. 每块主差 D = mean(WS_C) − mean(WS_E)，假差 Z = mean(WS_N+) − mean(WS_N−)。八块等权，分别给出均值及按块的双侧 95% Student t 区间（df=7，临界值 2.3646242516），不把各秒视作独立重复。此区间是近似值，依赖不同时间块差值近似独立。为防残余漂移，要求空对空差的 RMS ≤ 1.5 且 Z 的整个区间位于 [−1.5,+1.5]；另外要求前四块和后四块 D 均值对门槛同侧才可定向裁决。所有比较使用未舍入数值。
5. 通过质量与稳定性检查后，D 区间上界 ≤ +1.5 为 WindowServer 达标；下界 > +1.5 为超标；跨线待验。仍以 C 的 App CPU 均值 ≤ 0.8%、C−E 的配对平均 phys_footprint ≤ 25,000,000 字节为其余两项判据。报告各条件均值、最近秩 P95、每块差、时间与原始读数。检查或稳定性未通过时 S4 整体待验。一次注册仅一次执行，无复跑；只允许对同一份原始数据复算。
